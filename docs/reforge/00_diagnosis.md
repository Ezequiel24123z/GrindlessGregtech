# Reforge Phase 0: diagnosis of v0.17.0 "MAX"

Diagnosis only: no gameplay change, nothing under `pack/` touched. Judged against the owner's NEW philosophy (Reforge brief): costs go up (quantity high and expensive, items and fluids; LV review only, MV to MAX full rebalance, every input automatable, no inflated times); quests longer and more numerous in advanced eras and each era teaches its wafers, circuits, processes and multiblocks; the pack stays huge and industrial (remove pointless complexity, never meaningful); no manual grind, every byproduct has an honest destination; no save-compatibility rules.

**Evidence base.** Baseline dump `v0.17.0-max` (run 20261031-224215-server-5aa, commit 63fd5d16, MAX reachability PASS: gate 1063/1064 +1 warning, auto 401/401, eras 10/10). Existing audits were rerun on it (obtain pass, recipe-cycles, recipe-quality, process-audit, structure-quality, emi-coverage, quest lint); no new bench dump. New: `tools/analysis/census.mjs` (counts and the lists below). Full lists live in `docs/reforge/data/00_*.csv|json`; this file cites them instead of repeating them.
Command: `node tools/analysis/census.mjs --dump <dump> --errors <run/kubejs-errors.txt>`.

## 3. Broken or suspicious content

### 3.1 Recipes over their recipe type's slot limits (high)
`kubejs-errors.txt` has 67 warnings (66 recipes; `grindless:assembler/cofe_target` twice) "Trying to add more inputs/outputs than RecipeType can support". GTM 7.5.3 only warns and keeps every ingredient (integrator check on the v0.17.0 native dump: `grindless:assembler/gtca/mega_lcr` loads with 2 fluid inputs, `grindless:assembler/platinum_plant` with 10 item inputs). The capacity lint (`tools/analysis/capacity-lint.mjs`, RF-1A) is the fuller list: 87 errors, 50 of them among these warnings plus 37 GTM never warned about (35 over the type's fluid limits, 1 over its item limit, 1 tank too small); EMI shows only the type's slots, so it hides the surplus. The other 16 warnings exceed the limit only by the programmed circuit, which machines keep in their own slot (whether GTM 7.5.3's EMI page shows that circuit is unverified). By era: uxv 16, uhv 14, uv 11, uiv 7, zpm 5, iv 3, opv 3, uev 3, ev 2, luv 1, max 1, unmapped 1 (`data/00_dropped_inputs.csv`). Typical causes: assembler fluid input limit 1, chemical reactor item input limit 2, cutter 1, assembler output limit 1 (five `mh_cable_*` in uiv, `xray_timing_head`), and `grindless:assembler/cofe_target` with 9 item inputs. This is a real defect (Phase 2): fix by routing the recipe to a type with enough slots or splitting it, never by removing the input.

### 3.2 Reachability, obtain and cycles
- Obtain pass verdict FAIL: 1,161 never-obtained items in 525 groups (B 15: GTM OpV hatches and converters, correctly hidden; C "will never arrive" 454; unclassified 56). The 56 unclassified groups are mostly MAX/OpV `nsc_belt`/`black_hole_orbit` chain items (e.g. `cooled_exhaust`, needing `flux_loaded_frc` in `gcyr:black_hole_orbit`), because `IMPLEMENTED_ERA` is `uxv` (`integration/hidden.js:36`) and `tools/analysis/tiers/obtain.json` has no OpV/MAX places. The reachability run itself passes, so this is stale tool config (Phase 3). The dump lacks `lookup_unreachable.json`, so the GTM recipe lookup was not checked (`data/00_obtain_never.csv`).
- Class C is mostly dead add-on content: GTNN "end-game circuits" (100 groups), GTCA (68 groups with no recipe), and orphan registered materials (SiC/SiC, thorium nitride, Wf/RHEA, YIG, ytterbium, erbium, CoFeB and others) with ore blocks but no vein. Candidates for Phase 8 removal or Phase 3 wiring.
- recipe-cycles: 0 cycles, 0 unreachable controllers, 0 used-but-unmade tier components. "234 unreachable tracked ids" is the number of tracked ids with no producer in the stand-in model, not a gate failure (not individually triaged here).
- 17 ore-refinery materials skipped, items missing: adamantium, bedrockium, cosmic_neutronium, cosmic_plutonium, endium, fayalite, fluorite, germanite, green_fuchsite, mytryl, ohriharukon, orundum, red_fuchsite, red_zircon, thaumium, vinteum (`ev/mega_ore_refinery.js:153`). Two fusion recipes named in the audit are not in the recipe manager (`uv/fusion.js:67`, `zpm/fusion.js:305`). 4 `wcwt:*` recipe parse errors come from a third-party mod's `forge:conditions` (not ours).

### 3.3 Cheap and mispriced recipes (recipe-quality, 284 findings, `data/00_recipe_quality.csv`)
C-COMPLEX 73, T-CIRC 45, T-COUNT 45, T-COMP 44, T-VOLT 39, T-HULL 38. The audit only scopes UEV, UIV and UXV, so lower and higher eras are unmeasured. Example: `grindless:assembler/atom_interferometer` (uev, `earth_orbit.js`) has 3 inputs of x1; `hftacn_coil_block` and `photonic_casing` are under-voltage. UXV is the worst for the T-* codes (20 each).

### 3.4 Process audit (36 findings, 18 new, `data/00_process_audit.csv`)
2 `no_use` (OpV), 3 `self_gain` (uv, zpm, max: a recipe returns more of an input than it consumes, e.g. `genome_archiving/genome_copy` 1 in, 2 out), 31 `trivial_step` (uxv 3, uiv 13, opv 8, max 7). These break "difficulty from meaningful steps, no silly recipes".

### 3.5 Unused, dead and duplicated content
- 48 `grindless:` items never consumed by a recipe, a quest, a machine or a structure (`data/00_unused_items.csv`): lv 30 (capacitor cells, wireless covers), max 8, steam 1, uv/uev/uiv/uxv 2 each, opv 1.
- 25 retired items (uev, uiv, uxv motor, pump, conveyor, piston, robot arm, sensor, emitter, field generator, plus `vein_sample_scheelite`) are hidden "for old saves" with 1:1 conversion recipes; 11 gtceu dust and ingots are hidden "until their era". Save compatibility is no longer a rule: remove all of it (Phase 8).
- Duplicate recipes: none (same type, inputs and outputs under different ids; `data/00_duplicate_recipes.csv`).
- Dead add-on content: GTCA, GTNN and GCYR registrations with no recipe or no route (see 3.2). Dead code was checked only at this level; a function-level dead-code pass was not done (Phase 8).

### 3.6 Quests pointing at wrong items
`grindless:vein_sample_{bauxite_end,magnetite_end,sheldonite,zirconium}` are HV-era items used in `mv_age` (`data/00_quest_refs.csv`). All other quest items resolve in the dump. Hidden-item and obtain-never checks of quest items were not cross-run here; lint does not check item ids. 10 quest layout warnings: lv_age 3, mv_age 2, opv_age 5 (0 errors).

### 3.7 Missing lang, textures and sounds
- Lang: en_us 8,320 keys, es_es 8,512. 192 keys exist only in es_es (e.g. `item.gtceu.samarium_chloride_dust` and its small and tiny forms, a pattern for add-on dusts); no key is missing in es_es (`data/00_lang_gaps.csv`).
- Textures: 211 registered `grindless:` items or blocks without an item or block texture file, concentrated in lv 69, uxv 44, steam 22, luv 13 (`data/00_asset_gaps.csv`; the check is by file name, so items that use a generated or shared model may be false positives).
- Sounds: 62 `loop_*.ogg` against 288 multiblocks; 243 multiblocks have no loop sound of their own (worst uhv 31, uv 29).

## 6. Unproven or unmeasured
- The Expanded Assembly Line (formation, research path) was never tested in game (QR-G0). Every shape forms from its own preview on the bench, but the formed looks were never screenshot-reviewed (`docs/STATUS.md`).
- Not measured here: whether each input of MV to MAX is automatable end to end; fluid and item scaling inside generated table recipes (976 unmapped recipes); a function-level dead-code pass; hidden or obtain-never items referenced by quests; era "open questions" in `docs/eras/*.md` (not read, by rule).
- Era counts are registrations by script folder and mapped recipes, so 976 table-generated recipes are unattributed; treat the per-era numbers as relative, not absolute.
